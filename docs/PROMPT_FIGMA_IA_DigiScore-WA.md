## PROMPT À COPIER-COLLER

```
You are a senior product designer generating HIGH-FIDELITY UI mockups in Figma for DigiScore-WA, a microfinance credit copilote for West African SFDs (sample institution: FUCEC-Togo), built during a 72h CIF DigiCoop-WA+ hackathon (Track A, Theme 02 — Microcredit Scoring).

Read carefully the attached project plan Markdown. Treat it as the single source of truth for flows, roles, modules, scoring logic labels, and out-of-scope items. Do NOT invent features that contradict the plan. Do NOT design a generic neo-bank consumer app.

???????????????????????????????????????????????????????????????
0) PRODUCT ONE-LINER (must be visible in the design system / cover)
???????????????????????????????????????????????????????????????
DigiScore-WA is NOT an auto-approving robot. It is a human copilote that:
1) requires an existing MEMBER ACCOUNT before any credit application;
2) scores using institutional HISTORY (savings, movements, past loans, incidents) + today’s field form;
3) outputs like mobile airtime credit in Togo: eligibility + score/1000 + eligible amount (plafond) + explicit business MESSAGE;
4) routes decisions through Agent de crédit ? Chef d’agence ? CIC (committee). The system never takes the final decision alone.

WA = West Africa.

???????????????????????????????????????????????????????????????
1) DESIGN GOALS
???????????????????????????????????????????????????????????????
- Primary users: credit officers in agencies with intermittent connectivity, Android phones + Windows laptops.
- Mobile-first PWA, then responsive desktop for Chef d’agence and CIC review queues.
- Clarity and auditability over decoration. Every score must feel EXPLAINABLE (show criteria breakdown, knock-outs, messages).
- Field realism: dense but calm forms inspired by FUCEC questionnaire parts A–E and proof levels N1/N2/N3 — not a marketing landing page.
- Support degraded/offline feel: subtle “sync pending / weak connectivity” states on Agent screens.

???????????????????????????????????????????????????????????????
2) VISUAL DIRECTION (STRICT)
???????????????????????????????????????????????????????????????
Brand / UI direction for DigiScore-WA:
- Professional institutional fintech for cooperatives — trustworthy, sober, West African context without clichés.
- Color system (CSS-like tokens):
  --navy: #0B3D5C (primary)
  --teal: #1A6B5C (accent / success-ish actions)
  --sand: #F4F1EA ONLY as tiny surface accent if needed — do NOT make the whole app cream+serif terracotta (avoid that AI cliché)
  --surface: #F7FAFC
  --card: #FFFFFF
  --text: #1A1A1A
  --muted: #5C6B73
  --danger: #B42318
  --warning: #B54708
  --ok: #027A48
- Typography: distinctive but readable — prefer a clean humanist sans for UI (e.g. “Source Sans 3” / “IBM Plex Sans” / “DM Sans”). Avoid Inter/Roboto/Arial defaults if the tool allows alternatives. Avoid decorative display serifs in the app chrome.
- Radius: 8–12px. Light borders, soft soft shadows. NO neon glow, NO purple-indigo gradients, NO glassmorphism overload, NO emoji as UI icons.
- Icons: simple line icons (user, wallet, alert, scale, stamp/approval).
- Score visualization: clear gauge or segmented bar 0–1000 with zones:
  0–400 danger (rejet recommandé)
  401–700 warning (analyse / CIC)
  701–1000 success (approbation recommandée)
- Always show side-by-side: Montant demandé vs Montant éligible (plafond).
- Message banner styled like telecom operator feedback (short, explicit FR copy).

Language of ALL UI copy: French (Togo / WA). Keep labels short and operational.

???????????????????????????????????????????????????????????????
3) INFORMATION ARCHITECTURE — 3 ROLES
???????????????????????????????????????????????????????????????
Create separate app shells / navigation for three roles (demo logins: agent / chef / cic):

A) AGENT DE CRÉDIT
Mission: receive applicant, verify member, fill form, generate score/plafond/message, build memo, submit to Chef.

Screens (mandatory):
A1. Login (role selector or credentials)
A2. Home Agent — search member by n° compte / name; recent dossiers
A3. Member profile (CRITICAL):
    - identity, agency, membership seniority
    - account status (actif / gelé)
    - savings snapshot (solde, moyenne 3/6/12 mois)
    - past credits list (statut, retards)
    - incidents
    - “profondeur historique” indicator + thin-file badge if applicable
    - CTA “Nouvelle demande” DISABLED if non-membre / compte inactif
A4. Blocker empty state: Non-membre / compte gelé with message NON_MEMBRE
A5. Credit application wizard (steps aligned to FUCEC):
    Step 1 — Demande (objet, montant, durée, produit)
    Step 2 — Ménage / identification complémentaires
    Step 3 — Activité
    Step 4 — Revenus & charges
    Step 5 — Garanties & références
    Step 6 — Preuves N1/N2/N3 per sensitive field (chips or badges on fields)
    Show progress; allow save draft.
A6. Analysis result (HERO screen for pitch):
    - Score /1000 + zone
    - Breakdown of 6 criteria with weights:
      Analyse financière 25%
      Capacité de remboursement 20%
      Historique de remboursement 20%
      Risque d’activité 15%
      Garanties 10%
      Qualité documentaire 10%
    - Knock-out alerts if any (RCSD < 1.0, ESG, incohérence, incidents…)
    - Montant demandé | Montant éligible | optional “upsell possible” suggestion (not auto-grant)
    - Message code + human message (examples below)
    - Top 3 explications métier (why this score)
    - CTAs: Générer mémo · Soumettre au Chef · Modifier dossier
A7. Mémo de crédit preview (6 rubrics) + fiche comité 1 page
A8. Amortization table preview (calibrated; never above capacity)
A9. Weak connectivity / offline queue toast or banner

B) CHEF D’AGENCE
Mission: first validation level.

Screens:
B1. Queue “Dossiers à valider” (filters: zone score, thin-file, exceptionnel)
B2. Dossier review detail (read-only form summary + score panel + history strip)
B3. Decision actions: Valider · Refuser · Renvoyer à l’agent · Envoyer au CIC
    — if decision ? system recommendation ? mandatory motif modal
B4. Confirmation + audit stamp (who, when)

C) CIC (Comité)
Mission: final decision, especially grey zone & exceptional amounts (~8–10M+ FCFA).

Screens:
C1. Committee queue
C2. One-page synthesis for committee (printable feel)
C3. Decision: Accorder · Conditionner · Refuser (+ conditions fields)
C4. Simple PV / decision record

Also design TWO vision mockups (not full product, clearly labeled “Vision / Maquette M6-M7”):
M6. Portfolio monitoring: today’s due loans, early alerts (12 signals concept), PAR 30 / PAR 90 widgets
M7. Recovery prioritization matrix (4 levels) + action log

???????????????????????????????????????????????????????????????
4) BUSINESS MESSAGE EXAMPLES (use real FR copy in UI)
???????????????????????????????????????????????????????????????
- NON_MEMBRE — Ouverture de compte préalable obligatoire
- HISTORIQUE_INSUFFISANT — Historique institutionnel insuffisant pour ce montant
- EPARGNE_SOUS_SEUIL — Volume d’épargne / activité inférieur au seuil requis
- INCIDENTS_RECENTS — Comportement de remboursement non conforme
- MONTANT_PLAFONNE — Montant demandé supérieur au plafond : X FCFA proposés
- MONTANT_OK — Demande dans le plafond
- UPSELL_POSSIBLE — Capacité estimée jusqu’à Y FCFA (suggestion)
- VOIE_EXCEPTIONNELLE — Montant exceptionnel : passage CIC + garanties renforcées
- REJET_SCORE — Rejet recommandé — motif …

???????????????????????????????????????????????????????????????
5) ROUTING RULES TO REFLECT IN UI BADGES / QUEUES
???????????????????????????????????????????????????????????????
- Score < 400 or knock-out ? badge Rejet recommandé
- 401–700 ? badge Analyse CIC obligatoire
- > 700 and amount ? eligible and not exceptional ? badge Validation chef simplifiée
- Exceptional large ticket ? badge Voie exceptionnelle / CIC obligatoire
- thin_file=true ? badge Historique léger

???????????????????????????????????????????????????????????????
6) DEMO DATA SCENARIOS (design 3–4 filled states, not empty wireframes only)
???????????????????????????????????????????????????????????????
Populate realistic FCFA amounts and Togolese-style fictional names:
1) Good payer, regular savings — MONTANT_OK or slight upsell
2) Good profile but requested amount above plafond — MONTANT_PLAFONNE
3) Thin-file (account opened 6 weeks) — HISTORIQUE_INSUFFISANT / micro-plafond
4) Grey zone 401–700 — forces CIC path
Optional 5) Exceptional ~10M FCFA — VOIE_EXCEPTIONNELLE

???????????????????????????????????????????????????????????????
7) COMPONENTS / DESIGN SYSTEM TO GENERATE
???????????????????????????????????????????????????????????????
- App bars per role
- Member search
- Status chips (actif, gelé, thin-file, zones score)
- Proof level chips N1/N2/N3
- Score gauge + criteria list
- Amount comparison module (demandé vs éligible)
- Telecom-style message alert
- Wizard stepper
- Queue table (desktop) + card list (mobile)
- Decision action bar + motif modal
- Empty / error / offline states
- Cover slide: DigiScore-WA logo wordmark + tagline in FR

???????????????????????????????????????????????????????????????
8) DELIVERABLES EXPECTED FROM YOU (FIGMA AI)
???????????????????????????????????????????????????????????????
1. Cover + design tokens page
2. Mobile flows for AGENT (A1–A9) — high fidelity
3. Desktop (or wide tablet) flows for CHEF and CIC
4. M6 and M7 vision screens clearly marked as mockups
5. Component library page
6. One “Pitch demo path” frame linking: Member OK ? Result plafond ? Chef validate ? (optional) CIC

Do NOT design:
- Core banking replacement screens
- Live BIC / Flooz / Yas / SYSCOFOP integrations as working product UI (at most a future “connecteur” disabled/grey card)
- Dark-mode neon crypto aesthetics
- English-first UI
- Auto-approve screens without human confirmation

???????????????????????????????????????????????????????????????
9) QUALITY BAR
???????????????????????????????????????????????????????????????
- Consistent spacing (8pt grid)
- Accessible contrast
- Realistic content density for field officers
- Every critical screen must answer: Who is the member? What is the history depth? What is the score? What amount is allowed? What must the human do next?
- Align naming with the plan: DigiScore-WA, Agent, Chef d’agence, CIC, M1–M7, thin-file, plafond.

After generating, self-check against the attached plan Markdown and list any intentional omissions.
